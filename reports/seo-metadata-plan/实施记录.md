# SEO Meta 实施记录

日期：2026-10-30。45 个前台页面已写入本地项目，尚未发布线上。

- `src/data/seo.json` 是运行时逐页 Meta 的统一来源，包含完整标题、描述、H1 规划、索引策略、canonical 路径和对应分享图的实际尺寸。
- `src/utils/seo.ts` 将逐页设置合入页面原有信息，并保留文章发布时间、修改时间等原始信息。404 不输出 canonical；首页 canonical 保留根斜杠。
- 页面可见 H1 已同步。文章、产品、政策的标题及列表用语也已同步到各自来源；新增 side skirts 说明，避免“عتبات”被理解为承重踏板。
- OG 与 Twitter 都输出当前页的标题、描述和图片，标题品牌仅出现一次；文章作者分享标记使用出版责任页 URL。
- 站点地图读取同一份配置：40 页纳入，分类归档、3 个标签页及 404 共 5 页排除。后台另设 noindex,nofollow。
- 没有输出 meta keywords；没有新增未经验证的跨语言互链或跨域 canonical。

## 维护

修改 Meta 时维护 `src/data/seo.json`；若改 H1 或产品名称，也同步页面/产品数据中的可见标题，再运行验证。新页面未进入映射时使用原有页面 Metadata，不会被强制替换为首页内容。

`metadata-plan.json` 中 current 开头的字段和规划文档中的“实施前”文本保留旧值用于对照。规划生成脚本会重新读取构建结果，不应为了普通文案维护重新生成并覆盖历史基线。

## 验证

生产 HTML 逐页精确检查：Title、Description、H1、canonical、robots、OG、Twitter、文章时间和作者、站点地图纳入情况、重复标签和后台 noindex。详见 `implementation-verification.json`。

运行命令：

```text
npm run build
npm run check
node scripts/verify-seo-metadata.mjs
node scripts/verify-b2b.mjs
node scripts/verify-eeat.mjs
```

生产构建、Astro、ESLint、Prettier 及三组生产文件验证全部通过。浏览器视觉检查仍未通过审批系统执行，不能视为移动端、菜单及暗色模式已验证。部署后还需确认错误 URL 的真实 HTTP 404 响应，以及生产域名的抓取状态。
