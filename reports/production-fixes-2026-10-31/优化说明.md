# 线上审计问题优化

## 已实现

- 构建完成后自动输出 dist/_redirects，按当前43页SEO清单生成126条301规则：已知页面尾斜杠、index.html及.html别名归一到canonical；首页index.html归一；www域名重定向至正式主域名。规则只覆盖已知页面，不把未知路径跳回首页。
- 在HTML压缩后为56个mailto链接补入Cloudflare官方支持的email_off注释，避免邮箱地址被替换成依赖JS解码的链接。保留公开商务邮箱、邮件主题、无JS下直接mailto行为，以及Astro站内跳转后的入口。
- 新增 npm run check:hosting，验证所有已知URL别名、canonical无重定向循环、邮箱保护覆盖全部43页。

## 验证

生产构建成功；Astro、ESLint、Prettier通过。hosting、prelaunch、technical-seo、seo-metadata、b2b脚本通过；43页保持零本地表单。联系页浏览器展示及mailto目标检查通过。

## 发布及后台步骤

本次代码尚未推送或部署。部署时必须使用完整dist构建结果（其中包含自动生成的_redirects），不能仅上传public目录。Cloudflare Pages和Workers静态资源支持_redirects；Astro preview不会执行此平台规则，因此本地测试不等于线上已生效。

www重定向规则已备好，但DNS、证书和自定义域名绑定仍须在Cloudflare后台完成。不能仅靠仓库规则使不存在的www域名生效。

上线后复测：/vehicles/bmw/?ref=qa应301到无斜杠地址并保留查询参数；无斜杠canonical应200；未知地址应404；首页和站内跳转至联系页后的邮箱应仍为mailto；www完成域名绑定后应跳至amxnx.vip并保留路径。
