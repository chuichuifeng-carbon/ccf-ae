# 产品页 SEO、GEO 与搜索意图审计

审计日期：2026-11-03。结论：图片与采购入口有所加强，但本地新版存在发布阻断项，不建议原样上线。最紧急的是 URL 迁移、站内死链、结构化数据与售后信息一致性，其次是产品命名、分类和变体区分。

本次仅审计，未改写产品数据或页面模板，未提交 GitHub。新增审计脚本与报告保存检查结果。

## 范围与验证方式

- 读取当前未提交修改、产品生成器、60 条产品数据、产品模板、分类列表、BMW 入口及公共布局。
- 完成生产构建：115 个公开 HTML 页面，另有不纳入本次公开页面统计的 CMS 管理入口。
- 对全部公开页面检查标题、H1、描述、canonical、robots、链接、图片引用及 JSON-LD 解析；60 个产品逐页记录在 `产品逐页审计.csv` 与 `audit.json`。
- `npm run build`、`npm run check` 成功；后者包含 Astro、ESLint、Prettier。当时 Astro 检查 162 个文件，无错误、警告或提示。
- 复跑 10 个现有专项检查：1 个成功、9 个失败，见 `existing-checks.json`。很多失败由旧产品 URL 消失、元数据清单未同步触发，不能据此说 GA4 或所有对应功能本身都损坏。
- 正式域名抽查：博客、产品总览和旧 R44 产品页为 200，新 AX 产品页为 404。说明抽查时正式站仍是旧产品版本，本报告主要针对本地新版的发布前风险，并非断言这些问题已全部在线出现。
- 桌面产品首屏在浏览器中检查并保存 `product-desktop.png`；移动端未完成独立视口验证。没有 GSC、真实询盘归因、Core Web Vitals 或付费关键词数据，不宣称已收录、排名下跌、AI 引用或转化率变化。

## 发布前必须处理

### P0-1：4 个旧产品 URL 消失，已有文章仍链接到旧地址

`getStaticPaths()` 从原 `featuredProducts` 切换到 `allProducts`，新生成器改变了 slug 命名顺序或名称。以下旧地址不再生成：

| 原 URL 的 slug                                           | 状态与建议                                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| bmw-g80-g82-carbon-fiber-front-lip-r44-style             | 新数据有 r44-style-front-lip 命名；核对是否同一产品后保留旧 URL 或作一对一 301 |
| bmw-g80-g82-carbon-fiber-front-lip-three-piece-csl-style | 新数据存在 CSL 命名产品；核对三件套及材料后确定迁移目标                        |
| bmw-g80-g82-carbon-fiber-rear-diffuser-mp-style          | 新数据有 mp-style-rear-diffuser；核对组件范围后确定迁移                        |
| bmw-g87-m2-carbon-fiber-hood                             | 核对新 G87 机盖的实际款式和内容，不应随意指向机盖分类页                        |

这 4 个旧目的地址在构建页面中仍有 **20 处链接**，分布于博客等页面。原元数据记录仍保留，但保留元数据并不会生成页面或补上迁移。

建议：优先保留已发布 URL；必须更名时，确认产品等价后设置直接、无循环的 301，并更新博客、目录、canonical 与站点地图。不能把所有失效产品一律跳到首页或分类页。

证据：`src/pages/products/[slug].astro` 第 13 行附近；`audit.json` 的 `missingOldDetails`、`brokenDestinations`。

### P0-2：60 个详情页使用错误的博客路径，产生 420 处死链

本站文章实际位于根目录，而新模板写成 `/blog/文章slug`。

| 错误目的地址                                             | 出现次数 | 正确路径                                            |
| -------------------------------------------------------- | -------: | --------------------------------------------------- |
| /blog/dry-carbon-vs-wet-carbon                           |      180 | /dry-carbon-vs-wet-carbon                           |
| /blog/carbon-fiber-parts-fitment-check                   |      120 | /carbon-fiber-parts-fitment-check                   |
| /blog/carbon-fiber-import-cost-profit-guide              |       60 | /carbon-fiber-import-cost-profit-guide              |
| /blog/best-wholesale-carbon-fiber-suppliers-dealers-2026 |       60 | /best-wholesale-carbon-fiber-suppliers-dealers-2026 |

加上旧产品目的地址，共 **8 个失效目的地址、440 处链接，涉及 68 个页面**。这是渲染后 HTML 的逐链接统计，不是独立死链 URL 数量。

建议：使用现有 permalink 工具或正确根路径，并增加对全部构建 HTML 的目的地址检查。只检查 Markdown 文件或元数据清单会漏掉动态产品页。

证据：`src/pages/products/[slug].astro` 第 421、427、443、446、459、615、622 行附近。

### P0-3：60 页统一写入缺少逐产品依据的报价、库存和退货数据

产品 JSON-LD 硬编码 `AggregateOffer` 为 **USD 50–50000、InStock**，并硬编码 **7 天退货**。页面没有对应的实际逐 SKU 报价与库存展示，项目也未提供这些字段的产品数据来源。

现有售后政策说明的是干碳制造缺陷一年保修、到货明显缺陷 14 天报告、运输损坏 7 天报告等；不代表无条件 7 天退货。不能把报告期限改写成退货期限。

建议：未提供真实报价或可验证库存时删除这些报价、库存声明；退货标记只表达已经确认的政策。保留准确的 Product、Organization、BreadcrumbList 等基本语义。缺少真实报价/评价时可能不满足 Google 产品富结果资格，接受这一限制，不能补造数据来通过验证。

证据：产品模板第 109–125 行；`src/pages/return-refund-policy.md`。

### P0-4：上线检查清单与动态产品集脱节

产品由 4 页扩展为 60 页，但 `seo.json`、SEO 计划以及部分检查、图片站点地图和布局逻辑仍依赖旧集合。现在虽能构建，却不能通过原有发布质量门禁；工作流的 hosting 验证会因旧文件缺失而失败。

建议：统一产品、元数据、站点地图、结构化数据和审计的数据来源。改造检查以覆盖新路由，同时保留对旧 URL 迁移的断言；不能通过关闭检查或删除历史记录掩盖断链。

## SEO 与买家搜索意图

### P1-1：18 页落入 7 组完全重复的 Title、H1 和描述

主要重复组：

- 4 个 CSL 中网：带 ACC、不带 ACC、红碳等差异未进入标题与 H1。
- 前保险杠风口装饰与机盖风口装饰被叫成相同的“外部装饰件”。
- 中置排气扩散器套件与外框被叫成相同的“后扩散器”。
- G80/G82 进气套件、座椅背板、M4 车门被叫成相同的“定制碳纤维件”。
- G90 AX/MP 前唇、AX/MP 后扩散器分别没有体现款式差异。
- G90 电池盖、发动机盖板、水箱盖板被叫成同一个“定制碳纤维件”。

这比前面榜单文章的主题相近更直接：买家搜索部件或具体变体时，页面标题没有给出区别。它是意图区分不足及潜在自相竞争风险，不是已经发生关键词自相竞争的流量证据。

建议：以“部件 + 车型/底盘 + 款式/ACC/颜色/组件范围”组织标题和 H1，描述补充该变体的购买差异。真正只是颜色变体时，可以考虑合并成一个清楚的产品/变体页面；若保留独立页，应有独立图片与信息。不能仅因名称相似就把不同部件 canonical 到同一页面。

示例标题方向，需核对真实产品后应用：

- `شبك CSL كربون BMW G80/G82 مع ACC`：带 ACC 的 CSL 中网。
- `شبك CSL كربون BMW G80/G82 بدون ACC`：不带 ACC 的 CSL 中网。
- `أغطية ظهر المقاعد كربون BMW G80/G82`：座椅背板，而非泛称定制件。
- `غطاء حجرة المحرك كربون BMW M5 G90`：应进一步核对是发动机装饰盖板，避免与整块机盖混淆。

根因：`scripts/scan-products.mjs` 主要按目录生成品类与描述，款式只识别 `-XXX-Style`；未知名称退回通用品类。修改生成结果而不修生成规则，下一次扫描仍会复发。

### P1-2：6 件非前唇商品被归进前唇分类

包括 G80/G82 进气套件、座椅背板、M4 车门，以及 G90 电池盖、发动机盖板、水箱盖板。

建议：修正导入映射；进气件、内饰、车门与机舱盖板分别按实际品类归类。当前没有对应分类页时，应补充分组或入口，不能为获取流量强放到前唇分类。M4 车门是否同时适配 M3 也需要按实际产品确认，不能仅因父目录含 G80/G82 就默认共享适配。

### P1-3：4 件产品是站内孤立页，列表与车型入口没有完整覆盖

`ProductCollection` 默认只显示前 12 件，前唇组现有 17 件，没有后续分页/完整列表。4 页没有任何公开 HTML 页面指向它们：

- bmw-g80-g82-carbon-fiber-air-intake-kit
- bmw-g80-g82-carbon-fiber-seat-back-covers
- bmw-g90-carbon-fiber-engine-cover
- bmw-g90-carbon-fiber-radiator-cover

共 5 件产品没有出现在其所属分类列表，其中 G90 MP 前唇还能经 BMW 入口访问，另 4 件成为孤立页。XML sitemap 中存在不等于买家能从站内浏览到。

BMW 页面每个底盘“查看全部该底盘产品”的按钮都指向前唇分类，既未按底盘筛选，也不展示全部品类；原 `ModelCatalogs` 入口被移除，降低了按车型找目录的便利性。

建议：提供完整可抓取的分类列表或分页；BMW 底盘按钮连接到真实底盘分组/筛选页或对应锚点。产品分类、车型、具体产品应形成稳定的浏览链路。

### P1-4：详情页购买问题被泛化文案替代

目前有图片、车型、材料、规格表和 WhatsApp，这些方向正确。但 60 页大段相同工厂介绍、同一组 FAQ，缺少不同部件真正影响采购的答案。

| 买家问题           | 当前问题                                         | 建议                                                            |
| ------------------ | ------------------------------------------------ | --------------------------------------------------------------- |
| 到底是哪一件？     | 6 个通用名称、18 页重复标题                      | 写准确部件名称和变体                                            |
| 适配我的车辆吗？   | 按底盘目录自动套年份，泛称 1:1 无需修改          | 明确车身、改款、ACC、保险杠、排气及不适配情况，未确认项写待确认 |
| 收到哪些东西？     | 统一声称整套含全部固定件，且需拆原件             | 每款说明单件/对/套、覆盖件/替换件、配件与安装要求               |
| 批发怎么报？       | 有数量和目的地 CTA，但统一 50 件 MOQ/24 小时回复 | 使用实际政策或按订单确认，避免统一承诺                          |
| 值不值得选择这款？ | 主要用“高质量干碳”替代款式解释                   | 每件用短段解释 AX/MP/CSL、ACC、外框/整套等差异                  |

不需要把详情页写成大文章。推荐结构：准确名称与短答案 → 产品图片 → 适配/不适配 → 材料与包含内容 → 询价资料 → 相同车型或同类的少量相关产品。

### P2：描述截断、图片站点地图与相关产品排序

- 38 条源 meta description 被脚本机械截为省略号，部分句子不完整。字符长度不是 Google 硬性上限，但人为截断降低可读性；应重写成完整短句。
- 60 个新产品均已进入普通 XML sitemap，canonical 为本域自引用、robots 可索引；这些基础项正常。
- 60 个新产品均未进入图片站点地图，因为该集成仍要求 `seo.json` 显式记录。并不因此无法收录图片，但属于旧新数据源不一致，应修复。
- 同类/同底盘相关产品取原数组前几项，可能长期偏向某些款式；建议优先同底盘且同部件的可比较款，再补同底盘搭配件。
- 38 件主图 md/lg 原始宽度相同，模板 srcset 可出现相同宽度描述符。需去重，避免无效候选；现有技术集成还会再次处理图片，建议统一响应式图片管线。
- 新增 meta keywords 不能解决上述命名和内容差异问题，不应作为主要优化投入。

## GEO、实体一致性与可信度

### P1：结构化数据数量增加，但事实与实体定义不一致

60 个产品页都重复输出了 Organization：公共 `SiteIdentity` 已输出公司实体，产品模板又输出同一 `@id` 的不同公司定义。重复本身不自动等于错误，但本次名称、logo、sameAs、联系字段不同，且新 logo `/images/logo.svg` 文件不存在。

新 sameAs 包含本站两次及 WhatsApp 链接，未复用配置中的主站与公开公司资料；应统一引用配置中的实体，而不是额外创建一套。`WebPage.mainEntityOfPage` 指向 Product 的关系方向也不合适，可改为 WebPage.mainEntity 指向 Product，或 Product.mainEntityOfPage 指向 WebPage，并给 WebPage 稳定 `@id`。

新模板还统一写入 Toray T300/T700、135°C/6 bar、双层 UV 防刮、防黄多年、RoHS/Intertek、50 件 MOQ、无需改装、随件固定件等。项目中没有随每个 SKU 提供对应证据字段，且无需修改的承诺与现有售后页“可能需要调整”的说明存在张力。不能直接判断这些资料全部不实，但目前不足以逐商品验证。

建议：每款使用实际确认的规格与适配信息；工厂层面的能力放在 About/制造介绍中，不能自动等于每件产品参数。未知信息引导买家确认，不做绝对承诺。7 天运输损坏报告、保修期限与退货资格必须分别表达。

Google 的 AI 搜索指南明确：没有专门的 GEO schema 要求，重点仍是内容可抓取、可理解、准确，结构化数据与可见内容一致。添加 Speakable、HowTo、OfferCatalog 不会自动换来 AI 推荐。当前优先级应是真实产品答案与实体统一，而非继续堆 schema。参考：[Google AI features](https://developers.google.com/search/docs/appearance/ai-features)、[结构化数据通用规范](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)、[Product snippets](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)。

## 页面显示与询盘体验

- 60 个产品正文输出了字面量 `<bdi dir="ltr">G80</bdi>`，来自将 HTML 字符串直接放进 Astro 表达式；应输出实际组件节点，而非拼接 HTML 字符串。
- 同一段出现 `BMW BMW ...`、`جميع منتجات $...` 等模板痕迹。应修正，而不是把它视为关键词覆盖。
- 桌面首屏 H1 和长描述占据大量空间，产品图落在首屏之下；适配卡片的负上边距与 CTA 区域出现视觉接触/轻微重叠。建议短摘要、图文并列，移除不必要的负边距后复核手机端。
- WhatsApp 固定按钮替换方向符合询盘目标，但初始化只在脚本执行时调用，没有监听 Astro 页面切换事件。站内无刷新跳转后，初始显示状态依赖再次滚动；应验证首屏、切页、滚动恢复与无 JS 退化。普通页面 CTA 仍可用，不应把此点描述为 WhatsApp 全站不可用。
- 未检查到本地表单，图片 HTML 引用未发现缺失；保留了 WhatsApp 主要询盘入口。

## 优先修复顺序

1. 恢复/迁移 4 个旧 URL，修正 420 处博客链接。
2. 删除或校准没有真实依据的报价、现货与退货标记；统一公司实体。
3. 修生成器分类、部件与变体命名，重新生成后复核真实适配。
4. 补全分类/底盘入口，消除 4 个孤立产品。
5. 清理模板转义与绝对承诺，缩短首屏摘要。
6. 同步 SEO 记录、图片站点地图和发布检查，完成桌面/移动 QA 后再部署。

验收不应止于“build 通过”：还应确保旧 URL 正常或直接 301、全部内部目的地址有效、产品变体可区分、结构化数据与可见事实一致、所有在售产品可经站内入口访问、原有专项检查在更新后的数据集上通过。
